# LLM Data Analyst

A working prototype that shows how a large language model (LLM) can help someone analyse a dataset **without writing any analysis code themselves**. The user uploads a CSV file, asks a question in plain English, and the app returns a plan, the code, a table or chart, and a plain-language explanation.

## 1. What the app does

| # | Requirement | How the app meets it |
|---|-------------|----------------------|
| 1 | Upload a dataset | Streamlit file uploader accepts a CSV; a preview and a data profile are shown. |
| 2 | Ask questions in natural language | A text box takes the question; the **Analyse** button starts the analysis. |
| 3 | LLM generates a plan and code | The question plus a compact data profile is sent to the LLM, which returns a short analysis plan and one Python code block. |
| 4 | Execute using Python | The code is checked for safety, then run with pandas, numpy, scipy, matplotlib and plotly. |
| 5 | Display tables and visualisations | The app shows the `result_table` DataFrame and/or the chart (`fig`) the code produced. |
| 6 | LLM explains results in plain language | A second LLM call receives the results and writes a short, non-technical explanation with one caution. |
| 7 | Error handling and data/source references | Friendly error messages, automatic retries when code fails, and a "Data and sources" section listing the dataset, columns, libraries, model and attempts. |

## 2. How it works

```
 CSV upload ──► data profile ──► question ──► LLM: plan + code
                                                    │
                                                    ▼
                                         safety check (AST filter)
                                                    │
                          error? ◄── run code (pandas / plotly / matplotlib)
                            │                       │
         send error back to LLM (max 2 retries)     ▼
                                              table / chart
                                                    │
                                                    ▼
                                    LLM: plain-language explanation
                                                    │
                                                    ▼
                                         "Data and sources" panel
```

**Key design choices**

- **The LLM never sees the full dataset.** It receives a profile: row and column counts, each column's type, missing values, unique counts, min/max/mean for numeric columns, and 5 sample rows. This keeps requests small and limits how much data leaves the machine.
- **Structured output contract.** The system prompt tells the LLM exactly what variables to use (`df`, `result_table`, `fig`), which libraries are allowed, and what to avoid.
- **Self-repair loop.** If the generated code raises an error, the error message and the failing code are sent back to the LLM, which returns a corrected version (up to 2 retries).
- **Transparency.** The generated code is always shown in an expandable panel so the user can check what was run.

## 4. Setup (Windows)

1. Install Python 3 from <https://www.python.org/downloads/> (tick "Add python.exe to PATH").
2. Open Command Prompt in the project folder and run:

   ```
   python -m venv venv
   venv\Scripts\activate
   python -m pip install -r requirements.txt
   ```

3. Get a free API key from Google AI Studio (<https://aistudio.google.com>, "Get API key").
4. Create a file named `.env` in the project folder containing one line:

   ```
   GEMINI_API_KEY=your-key-here
   ```

   Optional: add `GEMINI_MODEL=<model name>` if the default model name stops working.
5. Start the app:

   ```
   streamlit run app.py
   ```

   It opens at <http://localhost:8501>.

## 5. Using the app

1. Upload a CSV file.
2. Check the preview and (optionally) the dataset profile.
3. Type a question, for example *"Is there a relationship between study hours and previous GPA?"*
4. Click **Analyse**. Read the plan, results, explanation and sources.

## 7. Error handling

- Missing API key: clear message telling the user what to add to `.env`.
- Unreadable or empty CSV: error message instead of a crash.
- Empty question: a warning, no LLM call.
- LLM or network failure: error message shown; the app keeps running.
- Generated code fails: the error is sent back to the LLM for a fix (up to 2 retries). If it still fails, the user sees a friendly message and a list of what went wrong.
- Explanation fails: a warning is shown, but the results remain visible.

## 8. Safety measures for running generated code

Running code written by an AI is the riskiest part of this design. Before execution, the code is parsed and rejected if it:

- imports anything outside an allow-list (pandas, numpy, scipy, matplotlib, plotly, math, statistics);
- calls blocked functions such as `open`, `exec`, `eval`, `compile`, `__import__`, `getattr`;
- uses file-reading or file-writing methods (`read_csv`, `to_csv`, `savefig`, and similar) or any dunder attribute (names starting with `__`).

The code also runs on a **copy** of the DataFrame, so the uploaded data cannot be altered.

## 9. Limitations

- **Not a true sandbox.** The checks reduce risk but cannot guarantee safety. A production system should run generated code in an isolated container with no network access, memory and time limits.
- **LLMs make mistakes.** The model can choose the wrong column, use an inappropriate method, or explain results with too much confidence. This is why the code is always visible and a warning is shown.
- **Limited view of the data.** The LLM sees only a summary and five sample rows, so it can miss unusual values, data-entry errors or hidden structure.
- **Statistical care.** The app does not check test assumptions (such as normality) and does not correct for multiple comparisons.
- **Privacy.** Column names, summary statistics and sample rows are sent to an external LLM provider. On the free Gemini tier, requests may be used to improve Google products, so sensitive or personal data should not be uploaded.
- **Model dependence.** Model names and free-tier limits change. During development the original model name stopped working for new users and had to be replaced.
- **Scope.** Only CSV files, one dataset at a time, and no memory of earlier questions.
- **Non-deterministic.** Asking the same question twice can produce different code and slightly different answers.

## 10. Troubleshooting

| Problem | Fix |
|---------|-----|
| `python` or `pip` not recognised | Install Python and tick "Add to PATH"; open a new Command Prompt. Use `python -m pip` instead of `pip`. |
| `ImportError ... websockets.frames` | Run `python -m pip uninstall -y websockets` then `python -m pip install "websockets<17"`. |
| 404 "model not found" | Set `GEMINI_MODEL` in `.env` to the model name suggested in the error message. |
| 429 / rate-limit error | Wait a minute and try again (free tier limits). |
| "No API key found" | Check that `.env` is named exactly `.env` (not `.env.txt`) and contains `GEMINI_API_KEY=...`. |
| Code error such as "No module named ..." | The LLM chose an unavailable library; the retry loop usually fixes this, or rephrase the question. |

## 11. Possible improvements

- Run generated code in a Docker container or restricted subprocess with timeouts.
- Support Excel files and multiple tables.
- Keep conversation history so users can ask follow-up questions.
- Let the user download the generated code and charts.
- Add automated tests with a fixed set of questions and expected outputs.
- Offer a local model option (for example via Ollama) for private data.
